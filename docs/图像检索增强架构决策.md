# 图像检索增强架构决策

## 决策范围

关键画面到视觉文本模型的后续接入将使用主项目内独立实现的图像检索能力。`no_training_vlm_retrieval/` 仅用于开发期阅读和对照；正式代码、测试、配置、构建和部署不得导入、调用或依赖该目录。

本阶段已将候选评估链路接为“关键画面候选 → DINOv2 检索 → Qwen3-VL + LoRA”。关键画面检测、
候选替换、事件 JSON 解析、接受条件、截图持久化和 memo 发布均保持原有职责与规则。

## 分层边界

- `domain/retrieval.py`：查询、索引元数据和检索结果的数据契约。
- `ports/image_retrieval.py`：图像编码器和检索网关协议；应用层只依赖这些协议。
- `services/image_retrieval.py`：标签路径规范化、祖先路径、L2 归一化和确定性余弦 Top-K 等无模型算法。
- `infrastructure/retrieval/`：DINOv2 本地编码、只读 NumPy 索引和组合后的本地检索网关。

冻结 DINOv2、Pillow 与 Transformers 在真正编码时才加载。仅加载既有索引、执行排序或运行单元测试时不需要 GPU、PyTorch 或 Transformers。

## 索引契约

运行时索引目录必须包含：

- `pool_embeddings.npy`：形状为 `N x D` 的有限浮点向量；每行对应一张图库图片。
- `pool_meta.json`：长度为 `N` 的对象列表；每项至少包含 `image`，可包含 `site` 和 `labels`。

推荐元数据格式：

```json
{
  "image": "gallery/image-001.jpg",
  "site": "dive-001",
  "labels": {
    "biota": ["Biota > Fish"],
    "substrate": ["Substrate > Sand / mud"]
  }
}
```

`index_manifest.json` 为可选校验文件；若存在，`count` 和 `embedding_shape` 必须与实际文件一致，`l2_normalized=true` 表示图库向量已经归一化，可避免每次查询重复处理整库向量。

读取异常、维度不匹配、向量非有限值、元数据数量不一致或不合法标签均以 `ImageIndexFormatError` 明确失败；图片缺失、模型依赖缺失和 DINOv2 编码失败使用 `ImageEmbeddingError`。后续监测链路接入时将依据这些异常记录状态，并按配置决定是否退化到原有两图 VLM 流程。

## 索引构建

构建入口为主项目的 `scripts/build_image_retrieval_index.py`，不导入、调用或复制
`no_training_vlm_retrieval/` 的任何代码。它提供三个子命令：

- `scan`：扫描图库和 `captioning_*.json` 标注分片，输出可安全索引的图片数量与排除原因，不加载模型。
- `build`：以本地冻结 DINOv2 按批生成向量，通过临时同级目录写入后原子发布 `pool_embeddings.npy`、`pool_meta.json` 和 `index_manifest.json`。
- `verify`：以内存映射逐块检查全部向量为有限且 L2 归一化，检查向量行数、元数据记录数、清单数量和形状一致，并拒绝重复图片路径。

运行时产物应放在本项目的独立资源目录，例如服务器上的
`/projects/deep-sea-explorer-codex/app/runtime/image-retrieval-index`，不得写入参考目录。
`pool_meta.json` 保存相对于图片根目录的位置、第一层目录推导的站点，以及原始 CATAMI
标签；清单保存源目录、输入分片、编码器标识和所有筛选计数，便于重建和审计。

给定的标注分片仅包含图片文件名而不包含完整相对路径。图库中若某文件名在多个站点
出现，构建器无法安全判断标签对应哪一个文件，因此会排除该文件名的全部候选路径并在
清单中记录计数。该策略优先保证每一行向量与元数据的真实一一对应，而不是以错误标签
换取更高覆盖率。

服务器构建示例（先以 `scan` 核对筛选量）：

```bash
.venv/bin/python scripts/build_image_retrieval_index.py scan \
  --image-root /sevenH/deepsea_vlm/data/raw/benthicnet/extracted/compiled_labelled_512pix \
  --annotation-root /sevenH/deepsea_vlm/data/raw/customer_annotations/captioning_labelled

.venv/bin/python scripts/build_image_retrieval_index.py build \
  --image-root /sevenH/deepsea_vlm/data/raw/benthicnet/extracted/compiled_labelled_512pix \
  --annotation-root /sevenH/deepsea_vlm/data/raw/customer_annotations/captioning_labelled \
  --model-path /path/to/local/dinov2 \
  --output-dir runtime/image-retrieval-index \
  --device cuda --batch-size 32

.venv/bin/python scripts/build_image_retrieval_index.py verify \
  --index-dir runtime/image-retrieval-index
```

## 检索和标签规则

- 查询向量与图库向量均使用 L2 归一化，排名按余弦相似度从高到低；相同分数按原始索引顺序稳定排序。
- 调用方可提供当前图片 ID，检索会排除同一图库图片。
- 调用方可提供站点并启用同站点排除，检索会排除该站点的全部图库图片。
- CATAMI 路径统一为 `父类 > 子类` 的空格格式；类别名称中原有的 `/` 保留，不被误解为层级分隔符。
- 未来向事件模型提供范例时，`biota` 映射到 `organism`，`substrate` 映射到 `seabed_substrate`，`bedforms` 和 `relief` 映射到 `micro_topography`；该映射不改变原始索引标签。

## 后续接入约束

候选队列产生当前关键画面后，`MonitoringService` 通过 `ImageRetrievalGateway` 获取范例，
将范例的真实路径、相似度、原始 CATAMI 标签和映射标签写入 `retrieval_context`，再调用既有视觉模型。
Qwen 输入仍以“参考图 + 当前候选图”开头，随后追加 Top-K 范例图；提示词要求模型独立判断候选图，
范例不得直接成为事件结论。范例标签显示为映射类别和叶级标签，以避免 CATAMI 根类别污染既有事件 JSON 枚举。

检索网关、DINOv2 与 Qwen 通过现有 `InferenceCoordinator` 串行使用 GPU。索引通过 NumPy memory map
加载，DINOv2 在第一次查询时加载一次。索引或编码发生任意异常时，监测服务记录 `retrieval_degraded`
并将空检索上下文交给原有两图 VLM 流程，不中断会话候选队列。

正式接入前需要新增显式配置，包括检索启用开关、DINOv2 本地模型路径、索引目录、Top-K、设备和同站点排除策略。配置默认关闭，以保证未部署索引时维持现有行为。

## 服务器实测（2026-08-11）

正式索引已完成构建并验证：`158638 x 768` 的 L2 归一化 `float32` 向量，索引、元数据和清单均位于
本项目运行时目录。使用同一真实候选画面、第二轮 Qwen3-VL LoRA 和真实图库的单进程对比结果如下；
各档均成功通过既有严格结构化 JSON 解析。

| Top-K | 检索时间 | Qwen 时间 | 本进程 CUDA 峰值分配显存 | 结论 |
| --- | ---: | ---: | ---: | --- |
| 0 | 0.00 s | 4.64 s | 4.41 GB | 原两图基线 |
| 2 | 0.17 s | 4.02 s | 4.85 GB | 可用 |
| 4 | 0.05 s | 3.55 s | 4.94 GB | 默认值 |
| 8 | 0.06 s | 5.89 s | 5.14 GB | 当前样本收益不足以抵消延迟 |

因此保持默认 `IMAGE_RETRIEVAL_TOP_K=4`。上述数字为单一样本的工程资源基线，不能代替正式 720p
视频的识别收益与误报率对比；启用在线 API 后仍须完成该端到端验收。

开发服务器若由人工环境变量启动且项目目录没有通用 `.env`，可在忽略 Git 的
`runtime/image-retrieval.env` 中仅保存 `IMAGE_RETRIEVAL_*` 配置。`deploy/run-api.sh` 会在
启动 Gunicorn 前加载它；该文件不得保存模型服务认证、语音凭据或其他敏感值。

最终验收将由项目负责人删除或隔离 `no_training_vlm_retrieval/`，随后重新执行安装、单元测试、服务启动和完整监测验证。

## 结构化事件输出稳定性

真实 720p 监测表明，Qwen3-VL 在少量候选事件上可能产生不完整 JSON，或把 CATAMI 根类别写入
`new_elements.category`。这两种情况均不能放宽既有的事件 JSON 解析或接受条件：不符合契约的
结果不能直接发布为 memo。

因此候选事件的首轮多图推理使用 384 个输出 token，并显式关闭 Qwen3-VL 的思考模式，以免隐藏推理
占用结构化输出预算。若结果仍不能通过既有严格解析器，适配器仅对原始文本发起一次无图的结构化重整，
同样关闭思考模式并使用 384 个输出 token：它不得新增观测、要素、数量或结论，且重整结果仍必须重新经过
同一个 JSON 解析器和事件接受规则。已知 CATAMI 根类别 `Biota`、`Substrate`、`Bedforms`、
`Relief`、`No bedforms`、`Bioturbation` 和 `Flat` 会规范化为既有四类事件类别；未知类别仍会被
拒绝。两次输出均不合格时，适配器只返回保守的 `survey_value=false`、`event_type="none"` 结果；它不会
发布 memo 或放宽任何事件接受条件，但会让候选队列继续处理可替换的后续候选，避免实时监测出现任务失败。
