# 图像检索增强接入与服务器验收开发交接

> 记录范围：图像检索增强接入、开发服务器部署与验收、关键帧检索审阅导出。
> 本文用于后续开发交接；不记录 `.env` 实值、Token、密码、私钥或模型服务凭据。

## 1. 已完成目标与系统链路

关键画面候选的评估链路已由原来的：

```text
参考关键画面 + 当前候选图 -> Qwen3-VL
```

调整为：

```text
参考关键画面 + 当前候选图
  -> DINOv2 对当前候选图检索图库 Top-K 范例
  -> 参考图 + 当前图 + 检索范例图/标签 -> Qwen3-VL
  -> 严格事件 JSON 解析、既有接受规则、memo 发布
```

- 检索范例只提供辅助识别信息，模型仍必须独立判断当前候选图；范例标签不能直接成为事件结论。
- 检索不可用、索引异常或编码失败时，监测会记录 `retrieval_degraded`，并自动退回原有“两图 -> VLM”流程，不中断会话或候选队列。
- Qwen3-VL、DINOv2 共用现有 `InferenceCoordinator` 串行访问 GPU，避免并发争抢显存。
- 当前已按项目负责人要求切换为 Qwen 基座模型评估：运行时覆盖文件中 `QWEN_ADAPTER_PATH` 为空时使用基座模型；该文件不存在时保持上层启动环境的模型选择。切换后须重启或向正确的 API Gunicorn 主进程发送 HUP，并重新验证健康检查和一轮监测。

## 3. 检索索引与配置契约

### 3.1 索引

服务器运行时索引位于项目独立运行时目录：

```text
/projects/deep-sea-explorer-codex/app/runtime/image-retrieval-index/
  pool_embeddings.npy
  pool_meta.json
  index_manifest.json
```

- `pool_embeddings.npy`：`N x D`、有限 `float32`、L2 归一化的图库向量。
- `pool_meta.json`：与向量逐行对应，至少有图片相对路径；可含站点和原始 CATAMI 标签。
- `index_manifest.json`：可选但推荐；校验数量、形状、归一化状态、输入来源和构建统计。
- 构建器对图库图片与标注分片进行安全匹配。同名图片出现在多个站点而无法唯一对应标签时会排除，优先保证“向量-图片-标签”一一对应。

2026-08-11 的服务器构建与 `verify` 结果：`158638 x 768`，L2 归一化 `float32` 向量；正式产物在上述本项目运行时目录中，不在参考目录中。

### 3.2 非敏感运行时配置

检索专用配置保存在 Git 忽略的服务器文件：

```text
/projects/deep-sea-explorer-codex/app/runtime/image-retrieval.env
```

应只包含下列 `IMAGE_RETRIEVAL_*` 项，不放其他服务认证信息：

```text
IMAGE_RETRIEVAL_ENABLED=true
IMAGE_RETRIEVAL_INDEX_DIR=<本项目运行时索引目录>
IMAGE_RETRIEVAL_DINO_MODEL_PATH=<服务器本地 DINOv2 模型目录>
IMAGE_RETRIEVAL_TOP_K=4
IMAGE_RETRIEVAL_DEVICE=auto
IMAGE_RETRIEVAL_EXCLUDE_SAME_SITE=false
```

- 模板见 `.env.server.example`；不要将真实的服务器路径、认证值或完整 `app.env` 写入 Git。
- `IMAGE_RETRIEVAL_ENABLED=false` 是保守默认值；开启时必须同时有本地模型后端、索引目录和 DINOv2 模型目录。
- Top-K 合法范围为 `0` 到 `8`。已完成的真实候选图工程基线中，Top-K=4 的检索约 `0.05 s`、Qwen 约 `3.55 s`、本进程 CUDA 峰值约 `4.94 GB`，因此当前默认值为 `4`；这不是识别准确率结论，后续仍需用完整视频样本评估。

Qwen 模型选择使用另一 Git 忽略的可选覆盖文件：

```text
/projects/deep-sea-explorer-codex/app/runtime/qwen-runtime.env
```

- 仅允许设置 `QWEN_ADAPTER_PATH`。
- 为空表示强制使用 Qwen 基座模型；填写本地 LoRA 适配器目录表示使用微调模型。
- `deploy/run-api.sh` 在启动 API 前加载 `runtime/image-retrieval.env`；Qwen 覆盖由既有运行时加载逻辑读取。修改配置后不能只改文件，必须重启已确认属于本项目的 API Gunicorn，或按既有流程对其主进程发送 HUP。

## 4. 服务器部署与操作要点

### 4.1 隔离边界

| 项目 | 已采用约束 |
| --- | --- |
| 应用根目录 | `/projects/deep-sea-explorer-codex/app` |
| Python 环境 | `/projects/deep-sea-explorer-codex/app/.venv`（Python 3.11） |
| API | 回环地址 `127.0.0.1:9001`，Gunicorn |
| 语音服务 | 回环地址 `127.0.0.1:9009`，Gunicorn |
| 静态前端 | 回环地址 `127.0.0.1:19100`，`python -m http.server` |
| 本机访问 | 仅通过 `deepsea-codex` SSH 隧道；不开放或接管服务器公网端口 |

禁止修改或重启 Apache、Nginx、systemd、系统 CUDA/驱动、系统 FFmpeg、Mihomo、`/projects/deepsea_vlm`、已有 Conda 环境，以及任何其他项目进程。模型资源盘只读复用时，不得改写其中内容。

### 4.2 启动、停止与日志

服务器端统一管理脚本：

```bash
cd /projects/deep-sea-explorer-codex/app
./scripts/server/manage-development-system.sh status
./scripts/server/manage-development-system.sh start
./scripts/server/manage-development-system.sh stop
```

- 脚本只接受自己 PID 文件记录、并且命令行经项目路径校验的 API、语音、前端进程；端口被非本项目进程占用时会拒绝替换。
- PID 文件在 `runtime/development-{api,speech,web}.pid`，日志在 `logs/development-{api,speech,frontend}.log`。
- API 启动实际入口为 `deploy/run-api.sh`，其执行 `gunicorn --config deploy/gunicorn_api.conf.py deep_sea_explorer.production_wsgi:app`。
- API 是单 worker 的开发期进程，会话、memos、问答与未生成报告素材保存在内存中；重启或 HUP 前必须结束当前监测并生成/下载报告。
- 重启前先通过 PID 文件和 `ps` 确认目标；不得通过模糊 `pkill`、全端口扫描或强制杀死不明进程操作服务。

本地傻瓜式入口（双击）位于仓库根目录：

- `启动系统（真实摄像头）.vbs`
- `启动系统（视频模拟）.vbs`
- `关闭系统.vbs`

其底层使用 `scripts/manage-system.ps1` 和服务端管理脚本；模拟摄像头只接受 Y4M，不能直接使用 MP4。启动后仍需在页面手动点击“开始监测”创建会话。

### 4.3 发布/更新顺序

1. 在本机完成代码审查、针对性测试和 `git status` 检查；不提交运行时目录、模型、视频、报告、日志、`.env` 或密钥。
2. 服务器更新前先检查运行状态与工作树差异；服务器存在专属未提交改动时，不能用 `git reset --hard`、`git clean` 或覆盖式复制。
3. 同步代码后，确认 `.venv` 依赖和 `runtime/app.env` 可用；`runtime/app.env` 从 `.env.server.example` 派生且不提交。
4. 检查 `runtime/image-retrieval.env` 的启用状态、索引目录和 DINOv2 模型路径；必要时运行索引 `verify`。
5. 仅重启已确认的本项目 API；如同时更新前端/语音，再使用受管脚本启动对应服务。
6. 通过 SSH 隧道检查首页和 `GET /health`，完成一轮“开始监测 -> 出现 memo -> 结束 -> 生成报告”的人工验收。

## 5. 关键帧与检索图片审阅导出

为人工核对关键帧与实际检索结果，已增加只读导出链路：

| 位置 | 职责 |
| --- | --- |
| `scripts/export_keyframe_retrieval_review.py` | 只读 SQLite 事件库、复制关键帧、对每帧重新检索、生成清单 |
| `scripts/server/export-keyframe-retrieval-review.sh` | 服务器加载必要非敏感运行时配置并创建导出目录 |
| `scripts/export-keyframe-retrieval-review.ps1` | 本机经 SSH 执行导出并通过 SCP 下载 |
| `导出关键帧与相似图片供检查.vbs` | 本机双击入口 |

导出脚本从 `DATA_DIR/events.sqlite3` 以只读模式读取已接受事件，只接受位于 `DATA_DIR/captures` 内的图片路径；不会写入数据库、不会重启服务。服务器导出目录为：

```text
/projects/deep-sea-explorer-codex/app/runtime/retrieval-review-exports/review.*
```

本次完整监测导出的本地审阅包为：

```text
C:\Users\emc20\Downloads\DeepSeaExplorer-RetrievalReview-20260812-existing
```

核验结果：742 张关键帧、2968 张检索图（每帧 Top-K=4），约 415 MB。包内：

```text
key_frames/                  # 关键帧
similar_images/0001/...      # 每个关键帧的 Top-K 图片
review_manifest.json         # 帧、事件、匹配排名、相似度、站点、ID、标签
关键帧与相似图对比.html       # 离线浏览页面
review_browser_data.js       # HTML 自动载入的浏览器数据
```

`关键帧与相似图对比.html` 可直接双击离线打开，提供逐帧浏览、上一/下一帧、序号跳转、会话筛选、左右方向键、元数据展示及图片放大。清单中的 `image_file` 仅为文件名，图片真实路径为 `similar_images/<四位帧序号>/<文件名>`；页面已按该规则补齐路径。`review_browser_data.js` 是为规避浏览器双击 `file://` 页面时禁止 `fetch` 本地 JSON 而生成的可公开审阅数据副本。

## 6. 验收、质量与后续重点

已完成/已核对：

- DINOv2 索引构建、全量格式验证和真实图库检索。
- Top-K=0/2/4/8 的单样本资源对比，保持默认 Top-K=4。
- 真实监测已结束且已生成报告；关键帧与检索图已导出到本机。
- 审阅包目录中关键帧与检索图的路径全量核对通过；离线 HTML 和数据脚本通过 JavaScript 语法检查。
- 既有 Ruff 与 Mypy 问题已修复；后续改动仍应执行与变更相匹配的测试、`ruff check` 与 `mypy`。

仍应在后续版本完成或重复：

1. 以 720p 完整时长视频，分别在基座模型和 LoRA 模型、检索开关/不同 Top-K 下比较识别收益、误报率、端到端延迟和显存。
2. 删除或隔离 `no_training_vlm_retrieval/` 后，在干净环境安装依赖、运行测试、启动服务并完成全流程监测，作为独立性验收。
3. 每次修改 `runtime/image-retrieval.env`、`runtime/qwen-runtime.env` 或服务端代码后，明确记录实际模型模式、Top-K、索引版本和重启时间，避免审阅结果无法复现。
4. 新增或迁移索引时，先运行 `scan`，再 `build`，最后 `verify`；不可直接替换单个索引文件，必须保持三类产物及其元数据一致。
